# CLI PoC на четырёх задачах для Windows

Версия: 2026-10-01. Это исполняемая ограниченная диагностика для обычного Windows-терминала пользователя на существующих четырёх зафиксированных авторских задачах. При подготовке runner модели не запускались. Большой benchmark не возобновляется.

## Запуск

Из корня репозитория в Windows PowerShell 5.1 или PowerShell 7 при наличии Python 3.9+ и уже авторизованного пользовательского CLI 0.159.2:

```powershell
& .\docs\experiments\toy-poc-v1\run-poc.ps1 -CodexExe (Join-Path $env:LOCALAPPDATA 'OpenAI\Codex\bin\de8a38d2100ae498\codex.exe') -Run -AcceptUnverifiedModelAndIsolation
```

Используется предоставленный пользователем суффикс установки без публикации личного пути. Если приложение изменит расположение или версию executable, нужно пересмотреть адаптер, а не незаметно использовать другую версию. Путь к существующему Python можно передать через `-PythonExe`; иначе обёртка использует `py.exe -3` или `python.exe`. Ничего не устанавливается. Без `-Run` выполняется только предварительная проверка. ExecutionPolicy, credentials и постоянные настройки аккаунта и защиты не меняются. Если локальная политика блокирует скрипт, сообщите об ограничении; обходить его не следует.

[PowerShell-скрипт](../experiments/toy-poc-v1/run-poc.ps1) запускает [контроллер стандартной библиотеки](../experiments/toy-poc-v1/cli_runner.py). Параметры и пути команды проверены статически; **на Windows здесь она не выполнялась**. В облаке нет PowerShell-парсера, поэтому проверка синтаксиса PowerShell и исполнения на Windows остаётся невыполненной.

## Предварительная проверка и граница расходов

До inference контроллер проверяет checksum зафиксированных задач, нативный executable, версию, общую справку и справку exec, авторизацию ChatGPT и доступные переключатели возможностей. При наличии переменных окружения с API-ключом или переопределением провайдера он останавливается, не читая и не печатая секретные значения. Каждый inference запрашивает встроенный провайдер OpenAI и `forced_login_method="chatgpt"`; запасного платного API-пути, процедуры входа, установки или покупки кредитов нет.

[Официальный каталог моделей](https://learn.chatgpt.com/docs/models) содержит `gpt-6-luna` и `gpt-6.1-sol` с оговоркой о доступности для аккаунта и клиента. В проверенном CLI нет документированной подкоманды списка моделей без inference. Поэтому доступ аккаунта к обеим моделям остаётся неподтверждённым до их первой задачи; ошибка неподдерживаемой модели останавливает серию. Дополнительных модельных вызовов для discovery нет. Перед запуском проверьте остаток включённой подписки: CLI login не подтверждает остаток квоты и не исключает автоматическое использование уже имеющихся дополнительных кредитов. Контроллер не может принудительно обеспечить границу только включённой квоты; при неопределённости этой границы запускать его нельзя. Настройки кредитов и аккаунта он не меняет.

## Стратегии, маршрутизация и лимиты

W запрашивает `gpt-6-luna`, E — `gpt-6.1-sol`; оба запрашивают `medium` и уровень сервиса `default`. Фактические модель, effort и tier не подтверждены. Каждая задача и этап получают свежий CLI-вызов без resume/fork. Исходный порядок чередуется W/E и E/W по задачам. W-only фиксирует единственный ответ W. W→E повторно использует тот же артефакт W и добавляет один перехват свежим E только при нарушении зафиксированного видимого правила. E-only независимо получает исходную задачу. Циклов исправлений и повторов контроллера нет. Настройки повторов встроенного провайдера нельзя переопределить записью собственного провайдера; отключение внутренних транспортных повторов не заявляется. Сообщённые итоги этапа сохраняются полностью, а любая неполная квитанция или ошибка останавливает серию. Всего сравнительных вызовов: 8–12. Общий W учитывается один раз физически и по одному разу в каждой логической стратегии; оценки стратегий зависимы, это не независимые выборки.

Некорректный JSON кандидата — видимый провал. Отсутствие usage, ошибка процесса, таймаут, reroute, активность инструментов или неподдерживаемые события останавливают серию; они никогда не вызывают E. Передача содержит только исходный пакет, недоверенный кандидат и видимые основания. Существующая независимая алгоритмическая приёмка выполняется после фиксации кандидатов и хешей их байтов; скрытая приёмка никогда не управляет маршрутизацией. Скрытые тесты и эталонные ответы не помещаются в prompts и рабочие каталоги задач.

Отдельный параметр `-ForcedHandoffOnly` вместе с параметрами запуска выполняет ровно один W и один E на P03 в новом каталоге прогона, исключая их из сравнительных итогов. По умолчанию он выключен. Все бюджеты плановые: максимум 12 сравнительных этапов, 180 секунд на клиентский процесс, 16000 байт UTF-8 в prompt, пороги остановки после получения квитанции — 32000 входных и 4000 выходных токенов на этап и 384000 входных / 48000 выходных на весь прогон. Для этого адаптера они заменяют прежний гипотетический предел 4000 входных: пользовательский арифметический smoke уже использовал 15445 входных токенов. Проверенного жёсткого управления выходным token cap здесь нет; текущий этап может превысить пороги, проверяемые после квитанции, поэтому это не потолки расходов. Завершение клиентского процесса по таймауту не доказывает отмену на сервере. Нужно остановиться и сверить usage; автоматический повтор запрещён.

## Квитанции и ограничение фактической модели

Каждый уникальный приватный каталог прогона печатается в системной временной папке; предыдущие результаты не перезаписываются. Для каждого этапа сохраняются байты UTF-8 prompt, неизменённый stdout JSONL и отдельный stderr, argv, exit status, временные метки, хеш кандидата и запись журнала. Python передаёт CLI бинарный stdin через позиционный `-`, исключая различия кодирования и quoting нативного конвейера PowerShell. Сохраните каталог до очистки временных файлов. Исходные логи могут содержать приватные сведения runtime; автоматически публиковать их нельзя.

Парсер принимает завершённый свежий thread с одним turn и обязательными input/output-счётчиками. Usage за turn достаточно для учёта задачи и этапа; телеметрия каждого сетевого запроса не требуется. Thread ID сохраняется; отсутствующие request/response/turn ID, поля кеша и reasoning остаются `null`. Провалы и неполные квитанции остаются в журнале; полные итоги становятся недоступны, а явно названные суммы известных значений доступны для проверки. Нулевой кеш, сообщённый CLI, сохраняется как сообщённый, а не превращается в подтверждённое backend-измерение.

`input_tokens + output_tokens` складывает каждый сообщённый итог один раз. Cached input, cache writes и reasoning — отдельные сообщённые компоненты, которые повторно не прибавляются. Взаимоисключение cache read/write и некешированная тарифная категория не выводятся предположением. Пересчёта в деньги, квоту или экономию нет. Новый парсер этапов намеренно не использует прежний строгий валидатор одиночного сетевого вызова.

Изучены [документация JSONL](https://learn.chatgpt.com/docs/non-interactive-mode), [публичная схема событий](https://github.com/openai/codex/blob/main/codex-rs/exec/src/exec_events.rs) и [обработчик событий](https://github.com/openai/codex/blob/main/codex-rs/exec/src/event_processor_with_jsonl_output.rs). Текущий публичный код копирует суммарный usage thread в событие завершения, может подставить нули при отсутствии usage, отбрасывает уведомления проверки модели и выводит reroute как ошибочный item. Адаптер использует свежие threads, отклоняет квитанции с нулевым входом для непустого prompt и останавливается при ошибочных items. Эти публичные исходники не удостоверяют установленный Windows-бинарник. Документированного поля подтверждённой модели в адаптере нет: `actual_model=null`; отсутствие reroute не является подтверждением. Прогон явно помечается `COMPLETED_UNVERIFIED_MODEL_AND_ISOLATION`, а не подтверждённым экономическим сравнением Luna и Sol. Подтверждение в параметре запуска принимает это диагностическое ограничение, а не расходы сверх подписки.

## Изоляция и пределы доказательств

Каждый этап получает пустой временный cwd вне репозитория и логов. Загрузка документов подавляется; поддерживаемые возможности shell, исполнения, apps, plugins, browser, computer, delegation и memory отключаются для данного вызова. Контроллер использует ephemeral-сессии, read-only sandbox и запрет эскалации разрешений. Пользовательский конфиг для inference не загружается; существующая авторизация и управляемые политики сохраняются, постоянных изменений нет. Соответствующие настройки описаны в [справочнике конфигурации](https://learn.chatgpt.com/docs/config-file/config-reference).

Это ограничение инструментов по доступным средствам, **а не проверенная изоляция чтения файлов**. Управляемые и глобальные расширения могут сохраниться; JSONL не доказывает отображение каждого скрытого действия runtime. Наблюдаемые события инструментов делают прогон недопустимым, но обнаружение после выполнения не отменяет доступ. Поэтому алгоритм приёмки независим, а его секретность на обычном хосте не подтверждена. Подтверждённый эксперимент со скрытой приёмкой требует отдельно проверенного runtime с изоляцией чтения; параметр подтверждения не отменяет это научное ограничение.

## Проверка

[Тесты](../experiments/toy-poc-v1/test_cli_runner.py): прошли 16 синтетических проверок, включая синтетический локальный подпроцесс для байтового I/O, отсутствующие и некорректные счётчики, провалы процессов, повторы и конфликты квитанций, reroute и инструменты, учёт общей работы, эскалацию только по видимым сигналам и приёмку зафиксированных ответов. Существующий синтетический harness также прошёл. Предоставленные Windows-счётчики обёрнуты в явно синтетические события для проверки арифметики парсера: 15445 входных, 12032 кешированных, 0 cache writes, 5 выходных и 0 reasoning дают 15450 сообщённых input-plus-output, а не новое измерение. Арифметический ответ 42 и успешное выполнение Windows CLI — сведения пользователя; исходный Windows JSONL здесь не читался. При подготовке не выполнялись реальные сравнительные вызовы, запуск на Windows, тест PowerShell-парсером, discovery моделей аккаунта или проверка изоляции sandbox.
